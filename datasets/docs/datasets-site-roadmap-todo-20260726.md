# TODO — Student-focused awards website

Product roadmap and action plan. Each item needs a brief approved specification before implementation.

Items are grouped by stage and ordered by dependency, not by preference. Every item states what "done" means so progress is
verifiable rather than asserted.

## What exists today

3,091 award records · 2,372 distinct laureates · 14 prizes · 1901–2026 · 40 affiliation countries · 304 affiliations.
Twenty page templates including prize, category, year, winner, person, country, affiliation, subject, explorer, and map.
Technical SEO is already generated by `website/build.py`: canonical URLs, Open Graph tags, JSON-LD, chunked `sitemap.xml`
with index, and `robots.txt`. Five test modules exist in `tests/`. There is no CI, no site-wide search, and no domain.

## Critical path

```
Define success ─────────────► everything below is ranked against it

CI ─────────────────────────► accessibility gate ─┐
                              performance gate ───┼──► weekly update agent
Name + domain ─► launch ────► search submission ──┴──► inbound links
                          └─► analytics
                          └─► llms.txt

Content rework ─► classroom artifact ─► teacher feedback ─► translations ES/FR/DE ─► CJK
```

Four sequencing rules:

1. Nothing can be submitted to a search engine before the domain exists. The domain item blocks five others and is the
   most under-rated item on this list.
2. Do not translate before the content rework. Translating text that is about to be rewritten pays for the same sentence twice.
3. CI precedes both quality gates and the weekly update agent, which is specified to deploy only when every check passes.
   Today no such mechanism exists.
4. Teacher feedback needs something worth showing. It follows the content rework and at least one classroom artifact.

- [ ] Choose the site’s public name and domain, then prepare production launch infrastructure: static hosting, DNS, HTTPS,

  Done when: the site resolves over HTTPS on the chosen domain, deploys automatically from the default branch, and a

- [ ] Evaluate and select a CDN-backed static deployment platform, such as Cloudflare Pages/CDN or an equivalent. Compare

  Depends on: name and domain. Done when: the comparison and the chosen platform’s deployment workflow are documented, and
  a preview deployment is reachable for a pull request.
- [ ] Prepare the repository for public release: choose appropriate code, data, and content licensing; audit third-party
  assets and attribution; remove secrets, private data, backups, and generated files from tracked history; and add

  Done when: the working tree contains no `*.bak` or generated artefacts, licences cover code, data, and content

## 3 — Findability

- [ ] Submit the site to search engines and verify ownership. Register the domain in Google Search Console and Bing Webmaster
  Tools, submit `sitemap.xml`, confirm indexing, and monitor coverage and structured-data errors. Add IndexNow so the weekly
  update agent can notify engines when new winners are published.
  Depends on: name and domain, launch infrastructure. Done when: both properties are verified, the sitemap is accepted, a
  sample of prize, person, and country pages is confirmed indexed, and coverage errors are at zero or explained.
- [ ] Build inbound links and distribution. Technical SEO is already generated; without referring links it ranks nowhere.
  Prioritise Wikipedia and Wikidata references back to the relevant pages — the dataset is Wikidata-derived, so linking back
  is natural and high-authority — then open educational resource directories, science-education newsletters, and educator
  communities. Record every placement and follow each site’s own contribution and conflict-of-interest rules.
  Depends on: search submission, About page. Done when: a recorded list of live inbound links exists and referral traffic is
  visible in analytics.
- [ ] Add site-wide search. Search currently exists only inside the explorer and countries pages, so a student who knows a
  laureate’s name has no entry point except an external engine. Generate a static index at build time and filter it on the
  client; no server component.
  Done when: search is reachable from every page, finds any of the 2,372 laureates by name, degrades to a visible link
  without JavaScript, and stays inside the performance budget below.
- [ ] Generate a concise `/llms.txt` at build time with the site’s purpose, audience, update date, limitations, and links to
  the About, methodology, licensing, explorer, map, prize, and dataset entry points; treat it as optional agent guidance,
  not as a replacement for accessible HTML, structured data, the sitemap, or `robots.txt`.
  Depends on: About page, name and domain. Done when: `/llms.txt` is generated by the build, never hand-edited, and its
  update date tracks the database snapshot.

## 4 — Quality gates

- [ ] Full accessibility audit: keyboard, screen reader, contrast, zoom and reduced motion. Audit the site as it stands to
  establish a baseline, state a target conformance level, and enforce it thereafter. Schools and districts have procurement
  requirements, so a site aimed at classrooms that cannot state a conformance level is blocked from some of them.
  Depends on: CI. Done when: the target level is stated publicly, the audit findings are fixed or recorded with rationale,
  the map and explorer are fully keyboard-operable, `prefers-reduced-motion` is honoured, and an automated check runs in CI.
- [ ] Performance budgets for mobile and slow connections, especially Map and Explorer. Set explicit page-weight and
  interaction budgets, measure on throttled mobile, and fail the build when a page exceeds its budget.
  Depends on: CI. Done when: budgets are documented per page type, the map and explorer meet them on a throttled mobile
  profile, and CI fails on regression.
- [ ] Close and disclose the data gaps. 2,749 of 3,091 records have no biographical note, and 1,639 have no affiliation
  coordinates, so the map’s affiliation layer covers under half the dataset while presenting itself as complete. Birth
  coordinates and sex are each missing for 44 records. Fill what is reachable from existing sources, then show coverage
  honestly on the pages and the map rather than silently omitting records.
  Done when: coverage figures per field are published and generated from the database, incomplete records are visibly
  marked, and the map states what it is not showing.
- [ ] Show per-field provenance. Pages present Wikidata-derived values without saying where each came from, which weakens
  the site’s central claim to be trustworthy.
  Depends on: About page. Done when: each page links its values to their source and to the methodology section.

## 5 — Audience and content

- [ ] Rework the site's text and styling for a high-school audience: plain language, clear explanations, strong visual hierarchy, and accessible mobile presentation.
  Depends on: define success, accessibility baseline. Done when: reading level is checked against a stated target, every
  page type has been rewritten, and the accessibility and performance gates still pass.
- [ ] Add an “About this site” page covering its purpose, audience, data sources, methodology, limitations, and update process.
  Depends on: define success. Done when: the page is published and linked from every page, and states the data gaps from the
  quality section plainly.
- [ ] Show the dataset’s last-updated date in the shared footer, sourced automatically from the published database snapshot
  or build metadata so it cannot drift from the deployed data.
  Done when: the date is generated by the build, appears site-wide, and no code path allows a hand-entered value.
- [ ] Ship at least one classroom artifact. The roadmap discusses classroom fit but offers nothing a teacher can use in a
  lesson: no printable one-pager, worksheet, lesson starter, data download, or embeddable map. The `high_school_subject`
  field is fully populated across all 3,091 records and maps every award to a school subject — Biology, Physics, Chemistry,
  Math, CS, History, Lit, Arts, Economics, Earth Science. No other site offers that join, and it is currently unused as an
  entry point.
  Depends on: define success. Done when: a subject-first entry point exists and at least one downloadable or printable
  classroom resource is published and tested with a teacher.
- [ ] Add a clearly labelled “Fix this data” action for missing or incorrect information. Open a submission form prefilled
  with the page URL and stable record ID; request the proposed correction and supporting source, make contact details
  optional, protect against spam, and queue submissions for human review without writing directly to the database.
  Depends on: name and domain. Done when: a submission arrives in a review queue, no path writes to `awards.sqlite3`
  directly, and the review and response process is documented.
- [ ] Get structured feedback from high-school teachers on clarity, usefulness, classroom fit, accessibility, and missing
  context. Recruit through appropriate educator networks or communities such as Reddit, obtain consent, avoid collecting
  unnecessary personal data, and record findings and resulting roadmap changes.
  Depends on: content rework, classroom artifact. Done when: a recorded number of teachers have responded, findings are
  written up, and the resulting roadmap changes are committed.
- [ ] Add a “Learn more” page with short descriptions and curated links to reliable introductory material, including the Feynman Lectures and suitable books.
  Done when: every link is checked in CI and each entry says who it is for and why it was chosen.
- [ ] Add a “Will AI change research?” page based on clearly attributed primary material from Demis Hassabis and other research leaders; separate sourced claims from editorial explanation.
  Done when: every claim carries a citation to primary material and editorial commentary is visually distinct from it.
- [ ] Add an optional “Explain this” action beside selected award text. It should give a high-school-level explanation without replacing or altering the source text, and clearly identify AI-generated output.
  Depends on: content rework. Done when: the action is opt-in, the source text is never modified, and generated output is
  labelled wherever it appears.
